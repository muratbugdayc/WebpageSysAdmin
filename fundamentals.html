Practical Exercises

These are “ops style” tasks. If you don’t have a live system, treat them as paper-labs: explain what you’d do and what you expect to see.

Practical 1 — Identify core z/OS components

Goal: show you understand OS vs subsystem.
  • Write a short line explaining what an address space is.
  • List 4 subsystems/services you expect on a typical enterprise z/OS system (example: JES2, TCP/IP, RACF…).
  • Explain in 1–2 sentences what spool is used for.
Reveal expected answer shape
  • Address space: isolated virtual memory environment for running work.
  • Subsystem examples: JES2/JES3, TCP/IP, RACF, WLM, SDSF, CICS/Db2/IMS (depends on shop).
  • Spool: disk-based queue for job input/output and print data so work can be scheduled/managed reliably.

Practical 2 — “Legacy method” workflow (TSO/ISPF)

Goal: demonstrate classic navigation.
  • Describe how you’d go to ISPF 3.4 and list datasets under your HLQ.
  • Name one reason sites still rely on 3270 screens today.
  • Write 2 things you can check in SDSF related to jobs.
Reveal hints
  • ISPF 3.4 = dataset list utility; filter like HLQ.*
  • 3270 persists because it’s fast, stable, and integrated with legacy workflows/tools.
  • SDSF: job status, output, JES queues, spool files, return codes, syslog.

1) What is z/OS? click to expand/collapse
  • z/OS is IBM’s mainframe operating system designed for IBM Z hardware. It is built for secure, scalable, continuously available enterprise workloads.
  • Lineage: MVS → OS/390 → z/OS (compatibility and long-lived workloads matter).
  • Typical subsystems: JES, TCP/IP, RACF, WLM, CICS/Db2/IMS (shop dependent).
1-line useful info Subsystems provide services (batch, networking, security, transactions, databases) on top of z/OS.
2) How System Admins Interact With z/OS: Interfaces & Legacy Methods click to expand/collapse
  • Terminal emulators (3270 / TN3270) remain common: classic, fast, reliable operational workflows.
  • TSO provides command interaction; ISPF provides menus, tools, and editors.
3) Address spaces + virtual storage click to expand/collapse
  • Each address space has its own virtual storage view (isolation).
  • Paging/swapping concepts apply when memory is pressured.
